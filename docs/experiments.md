## Fine-tuning attempt 1 (e5-small, title-style training pairs) (2026-11-05)

**Result: no improvement on real questions.** On eval set v1 (49 questions), the
fine-tuned e5-small is **worse** than the base model: Recall@5 0.265 → 0.122, and the
95% paired interval of the difference lies entirely below zero. In the hybrid, the
difference is within noise (Recall@5 0.347 → 0.327, interval includes zero). n = 49 is
small, so the size of the drop is uncertain. For e5-small the paired intervals lie below
zero for Recall@5 and Recall@10 (chunk level) and for Recall@5, Recall@10 and MRR@10
(article level); for chunk-level Recall@1 and MRR@10 they include zero.

- **Validation improved, but the gain did not transfer to the test questions.** The
  Kaggle run reported a higher validation MRR@10 on held-out train chapters for the
  fine-tuned model than for the base model. **The validation numbers are TBD here** until
  the run's `training_log.json` is committed under `results/`, since every number in this
  document must come from a result file.
- **Settings were fixed in advance** (`docs/finetune-runbook.md`): pairs from train
  chapters only, epoch chosen on validation MRR@10, nothing changed after seeing test
  results. The test questions were not used for training or model selection.
- Training pairs (`results/training_pairs_stats.json`): 10,327 train pairs from 851
  articles in 54 train chapter groups; query types: article title 3,398, first sentence
  3,397, cross-language title 3,384, mixed 148. Validation: 1,573 pairs of the same four
  types from 10 held-out train chapter groups.
- Both runs used the same 49 question ids, corpus and eval set. The questions file and
  `v1.json` sha256 differ between the base and the fine-tuned runs only because the
  fine-tuned run read them with CRLF line endings; converting the committed files to
  CRLF reproduces both recorded hashes exactly.

Observations (descriptive only, n is small):

- The e5-small drop comes from the Russian questions: delta Recall@5 −0.348
  [−0.565, −0.174] on the 23 ru questions, against +0.042 [−0.083, +0.208] on the 24
  uz-Latn questions.
- e5-small: 4 questions got better, 13 worse, 32 unchanged (chunk level). Hybrid: 8
  better, 10 worse, 31 unchanged.

**Possible explanations: untested hypotheses, not findings.** None of these was tested.

- *Query style mismatch.* The training queries are article titles and first sentences
  (plus cross-language titles); the test questions are mostly colloquial user questions
  (37 of 49 tagged `colloquial`). The model may have learned to match title-like queries
  at the expense of question-like ones.
- *Validation of the same style as training.* The validation pairs use the same four
  query types, so a validation gain shows a better fit to that style, not necessarily to
  real questions.
- *Why Russian dropped more* has not been investigated; the cross-language title pairs
  are one place to look.

## Pilot 3: 49 real questions, eval set v1 (2026-11-05)

**49 questions are still too small to rank the methods.** The sample has 24 uz-Latn, 23 ru
and 2 uz-Cyrl questions; the 95% confidence intervals are 16 to 29 percentage points
wide, and for every metric the intervals of all three methods overlap. The README keeps
the real table at TBD until at least 80 questions are labeled.

- **This question set is frozen as eval set v1** (`data/eval/sets/v1.json`): the 49
  question ids, the sha256 of `questions.jsonl` and the corpus fingerprint (document
  sha256s, chunker version, `data/splits.json` sha256). The before/after comparison
  with the fine-tuned model is run on v1 only (`--eval-set v1`). Questions labeled
  later form v2 and are reported separately; see `docs/decisions.md`.
- Questions: labeling batches 1 to 4, written by the maintainer for chunks of the real
  test split and stored verbatim with tags. One question has two gold chunks. The two
  uz-Cyrl questions have uz-Latn gold chunks (the corpus has no Cyrillic documents).
- Settings: unchanged since pilot 1 (BM25 `fold+stem6`, multilingual-e5-small ONNX at the
  pinned revision, hybrid RRF k = 60, 100 candidates per retriever). **Nothing was tuned
  on these questions.**
- Consistency check: the 22 pilot-2 questions have exactly the same ranks as in pilot 2
  for all three methods; the run restricted to v1 and the run on the whole question file
  give identical results (today they contain the same 49 questions).
